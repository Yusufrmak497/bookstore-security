**Project: bookstore-security.** The CLAUDE.md agents (`gelistirici`, `test`, …) aren't available in this session, so I made the fix myself. Nothing is committed.

1. **Fix:** `main.py` no longer allows every origin. CORS now only accepts origins listed in `BOOKSTORE_ALLOWED_ORIGINS` (comma-separated, default `http://localhost:8000`; a `*` entry is ignored), only `GET`/`POST` methods, and only the `Content-Type` header. Credentials are still allowed, and the planted-issues list in the docstring is unchanged.
2. **Test:** I added `test_cors_restricted_to_allow_list` to `test_main.py`. It checks that an untrusted origin gets no CORS header and its preflight is refused, that `DELETE` and extra headers are refused, that the default origin works, and that the origin list is read from the env var. The full suite passes (`7 passed`). Against a copy of the old wildcard config, the new test fails because the server sends back `https://evil.example` with credentials allowed.
3. **Open items:** I didn't re-run Semgrep. Deployments must set `BOOKSTORE_ALLOWED_ORIGINS` to their real frontend origin or cross-origin requests will be blocked. A helper script and test copies are left in `/tmp/cors_vuln_check.py` and `/tmp/cors-vuln-check/` and can be deleted.
